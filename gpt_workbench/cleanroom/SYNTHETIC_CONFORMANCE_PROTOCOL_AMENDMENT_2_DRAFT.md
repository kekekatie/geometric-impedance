**Status: PROPOSED / NOT RATIFIED / NOT IMPLEMENTED / NOT RUN**

**Purpose:** replace an impractical repetition requirement for synthetic conformance with a layered,
truthful evidentiary protocol, without changing any scientific requirement.

This document is a proposal for crew review. It has no normative force unless and until it is
expressly ratified. Drafting it does not ratify, implement or execute any provision. It authorizes
no implementation change, study-data access, launcher or scientific computation.

## 1. Scope and non-change declaration

If ratified, this amendment changes only how synthetic implementation conformance is evidenced. It
does not change any scientific endpoint, feature, threshold, identity, random-number rule, gate,
route, configuration, study workload or confirmatory-run requirement.

All scientific production constants remain unchanged, including:

- the complete 9 configurations × 6 offsets = 54 patches;
- all five frozen radii;
- all six outer folds;
- all four PCA slabs;
- exactly 200 launches per patch;
- `B=1000` address/local-null repetitions; and
- exactly 200 capacity draws.

These constants continue to govern production and the eventual confirmatory study. Reduced
numerical execution in synthetic conformance is evidence about wiring, identities and behavior; it
is not a reduced scientific protocol and may not be used as one.

## 3. Proposed layered synthetic-conformance protocol

The following layers are proposed for ratification, subject to crew review. Conformance requires all
applicable assertions in every layer to pass. Evidence from different layers must remain separately
labelled; enumeration, component reference checks and production-wired numerical execution are not
interchangeable.

### Layer A — Exact components

Use independent references, invariants, negative tests and mutation tests for every production
geometry, feature, regression, residualiser, matching, capacity, aggregation, dynamics and routing
component. Tests must call the production component interface and compare it with an independently
derived expected value or property. A test fixture that returns a precomputed stage result is not
evidence that the corresponding production component executed.

The dynamics engines must be tested independently against their appropriate exact references. A
clearly identified synthetic dynamics adapter may be used elsewhere only for controlled workflow
runtime; its output is not evidence that coherent or classical scientific propagation executed.

### Layer B — Production-wired compliant slice

Run one frozen permutation-feasible configuration across all six offsets, with:

- at least 400 common rows per offset;
- four slabs containing at least 100 rows each;
- exactly 200 launches per patch;
- both engine-labelled branches;
- all five radii;
- all six leakage-safe outer folds and the frozen inner-fold structure; and
- observed, parity, shuffle, residual, position, far, local-null and capacity branches.

The production orchestrator, not a high-level backend stub, must own and call the production common-
population validation, motif registry and deduplication schema, physical/address/parity feature
construction, PCA slabs and launch selection, leakage-safe regression, controls, local matching and
recomputed address features, capacity fields and paired increments, aggregation, Westfall–Young,
gates and routing.

For numerical randomisation execution in this layer, predeclare and execute address repetitions
`b={0,1,999}` and capacity draws `{0,199}`. This fixed representative set is adopted because it
includes both endpoints and an interior address repetition while bounding fit cost. No alternative
set is proposed. Every non-executed identity remains mandatory in Layer C.

### Layer C — Full identity graph

Enumerate and validate without numerical fitting:

- all 54 patch identities;
- all 42,000 local-null identities;
- all 10,800 capacity identities;
- every required engine and fold axis;
- exact frozen labels, membership and order;
- seeds, keyed provenance and random-number consumption rules;
- synchronization and permitted reuse relationships; and
- completeness and uniqueness of the resulting identity graph.

Golden identity and seed values must be independently verified. Enumeration must never be described
as numerical fitting, fitted-object execution or scientific propagation.

### Layer D — Routing truth table

Use controlled, explicitly labelled inputs to exercise and assert every required final route:

1. coherent claim earned;
2. modifier withheld;
3. G0 failure;
4. G4 undefined;
5. compression;
6. survives frozen stress controls; and
7. mixed/undetectable.

Each case must assert exact gate state, membership, route and permitted claim language. Controlled
gate ingredients establish routing logic only; they are not evidence that upstream numerical work
occurred.

### Layer E — G0 barrier

Construct an exact first crossing at `t=8` and instrument every downstream boundary. The required
result is zero calls to beta, regression, residualisation, shuffle and other controls, local-null,
matching and capacity computations. No shortened time-window or post hoc recovery path is allowed.

### Layer F — Scheduling determinism

Run the layered workflow in forward and reverse traversal order and with one and two workers. These
must be genuinely distinct traversal and worker/scheduling paths, with identical keyed results.
Identity enumeration, routing fixtures and representative numerical slices may be combined to make
this proof, but each evidence category must remain explicit.

This layer does not require four repetitions of the complete confirmatory-scale fit workload. It
does require deterministic production wiring wherever numerical execution is claimed and complete
keyed identity equality across all four modes.

### Layer G — Scale declaration

Every conformance report must state three disjoint categories:

1. **Enumerated identities:** exact counts of identities whose labels, order, seeds, synchronization
   and reuse were validated without claiming numerical execution.
2. **Executed production functions:** exact invocation counts, by named production function and
   layer, including the exact number of fits and control computations actually run.
3. **Confirmatory-scale computations not executed:** exact counts and kinds of full-scale production
   computations omitted from synthetic conformance and reserved for the eventual confirmatory run.

No category may be inferred from another. In particular, enumerating an identity does not establish
that its fit, propagation or control calculation ran.

## 4. Mandatory production-bypass mutations

The conformance suite must demonstrate that bypassing or replacing any production feature,
residualiser, shuffle, matching, capacity, aggregation or Westfall–Young function causes failure.
At minimum, mutants must cover a fixed-result substitute, wrong-width output, wrong membership,
wrong label order and omitted call where applicable. Spies must establish that the production
function was actually invoked; the corresponding mutation must establish that the observed workflow
result depends on its output rather than merely counting a callback.

These tests supplement, and do not replace, independent component references in Layer A.

## 5. Fit-caching boundary

Fit caching is permitted only when the training matrix, target, fold identity, schema identity and
provenance identity are byte-identical. The cache key must bind all five items and reject any missing
or differing item. Test evidence must include deliberate one-field mutations for each item.

Before any scientific execution may use fit caching, cached and uncached predictions must be shown
to be bit-identical or equal within a single frozen numerical tolerance. That tolerance, comparison
domain and software environment must be declared before the scientific execution. Cache reuse may
not cross a non-identical training matrix, target, fold, schema or provenance identity, even when
shapes or summary statistics happen to match.

## 6. Claims and evidence boundaries

Layers A–F do not establish or permit a claim of:

- full-scale runtime feasibility;
- complete 9×6, `B=1000`, capacity-200 synthetic numerical execution;
- execution of any fit or component represented only by an enumerated identity;
- scientific propagation from a synthetic dynamics adapter; or
- any scientific outcome, confirmatory result or endpoint conclusion.

Passing the layered protocol is implementation-conformance evidence only. The eventual confirmatory
run remains responsible for every frozen production computation and scientific workload.

TP-E2E-003 remains unchanged and controlling:

> **TP-E2E-003 Exact component reference.** Tiny independent component fixtures may use direct
> matrix exponentials, fully materialised tensors, explicit OLS, exhaustive RowId joins and hand
> median/gate code. They may validate components but cannot claim a pass through the full production
> orchestrator unless every frozen common-set, slab and 200-launch floor is satisfied.

Accordingly, Layer A component-reference evidence is not workflow evidence. Only Layer B may supply
production-wired workflow evidence, and it may do so only while satisfying its full common-set, slab
and 200-launch floors. Layer C enumeration and Layer D controlled routing evidence must be reported
under their own names.
